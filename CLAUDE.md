# revise svt : consignes pour Claude

- Les pages des niveaux (`cinquieme/`, `premiere/`, `terminale/`) et de l'espace professeur (`prof/`) sont chiffrées avec le code d'accès de leur niveau par `_outils/verrou.py` (AES-GCM, clé dérivée du code par PBKDF2). L'accueil (`index.html`) et `assets/` restent en clair.
- Les codes ne sont écrits nulle part, ni dans le dépôt ni dans ce fichier : demander au professeur le code du niveau avant toute modification.
- Le dépôt est public : ne jamais committer une page de niveau en clair.
- Modifier ou ajouter une page :
  1. `python3 _outils/verrou.py ouvrir NIVEAU CODE /chemin/hors/du/depot` (déchiffre les pages du niveau) ;
  2. modifier les pages en clair dans ce dossier, puis les recopier à leur place dans le dépôt (une nouvelle page s'écrit directement en clair à sa place) ;
  3. `python3 _outils/verrou.py fermer NIVEAU CODE` (chiffre les pages en clair, vérifie que les autres s'ouvrent avec ce code) ;
  4. `python3 _outils/verrou.py verifier NIVEAU CODE`, puis vérifier qu'aucun texte en clair ne reste avant de committer.
- Montrer un aperçu au professeur et attendre sa validation avant toute publication sur le site.
- Évaluations : les copies des élèves sont envoyées à un script Google Apps Script du professeur (tableur Google) ; la page de correction est dans `prof/`. L'adresse du script et la clé de lecture ne figurent que dans les pages chiffrées.
- Évaluation de cinquième « L'évolution des espèces » : 4 sujets (A à D), un par groupe. À l'intérieur de la page (déjà chiffrée avec le code de cinquième), chaque sujet est chiffré à part avec le code de son groupe (PBKDF2 sur le sel `sha256("revise-svt/evolution-5e/sujet")[:16]`, AES-GCM) ; le code tapé par l'élève ouvre le seul sujet qu'il déchiffre. Les codes des groupes et les corrigés sont dans la page de correction (volet « Codes des sujets »), chiffrée avec le code professeur. La copie note les sorties de la page, les collages bloqués et la touche Impr. écran ; une page web ne peut pas empêcher une capture d'écran.
- Activités publiées masquées : la carte de l’activité dans l’index du niveau porte `data-en-ligne="niveau/dossier"` et l’attribut `hidden`. L’index lit `assets/en-ligne.json` (en clair, public) et n’affiche la carte que si `en_ligne` vaut `true`. Le professeur change cet état lui-même depuis l’espace professeur (page `prof/mise-en-ligne/`), qui écrit `assets/en-ligne.json` par l’API GitHub avec son jeton personnel (gardé seulement dans son navigateur, jamais dans le dépôt). Ce fichier peut donc changer sans passer par Claude : faire `git pull` avant toute modification.
- Cinquième, chapitre 2, activité 1 « Histoire des sciences : la reproduction sexuée » (`cinquieme/histoire-reproduction/`) : page autonome construite hors du dépôt (frise des théories et QCM, expériences de Spallanzani en simulation, tableau à remplir au clavier, questions 2 et 3 avec un guide et sans réponse modèle, copie PDF générée dans le navigateur de l’élève, à déposer sur Pronote ; champ « Groupe » au lieu de « Classe »). Documents d’après le manuel de SVT cycle 4 Hatier. Publiée masquée : carte avec `data-en-ligne="cinquieme/histoire-reproduction"`.
- TP 2 de Terminale « L’origine de l’ATP » (`terminale/origine-atp/`) : page autonome construite hors du dépôt (ExAO virtuelle ; fiche réponse PDF générée dans le navigateur de l’élève ; fiche de travail du bilan intégrée en PDF, version élève uniquement, jamais le corrigé).
